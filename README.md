# Local Preview Board

로컬에 있는 정적 HTML 사이트를 폴더째로 열어서, 여러 화면 폭(모바일/태블릿/데스크톱)을
한 화면에 나란히 띄워놓고 검수하는 단일 HTML 도구. 빌드도, 서버도, 설치도 필요 없습니다.

Chrome의 **File System Access API**로 폴더를 직접 읽기 때문에 하드코딩된 페이지
목록이 없습니다 — 어떤 정적 사이트 폴더에 갖다놔도 그 안의 `.html`을 자동으로 찾습니다.

[Local Web Inspector](https://github.com/yujeongkeem/LocalWebInspector) 와 같이 쓰면
좋습니다: 이 도구로 화면을 띄워놓고, 그 안에서 엘레먼트를 우클릭해 코멘트를 남길 수 있음.

## 사용법

1. `local-preview-board.html` 파일 하나를 검수하려는 로컬 정적 사이트의 **루트 폴더**
   (HTML들이 들어있는 폴더) 안에 복사합니다.
2. Chrome에서 그 파일을 엽니다 (더블클릭, 또는 주소창에 `file:///…/local-preview-board.html`).
3. 왼쪽 위 **"폴더 선택"** 클릭 → **방금 이 파일을 넣은 그 폴더**를 선택합니다.
   (다른 폴더를 고르면 미리보기가 깨집니다 — 이 파일 자신의 위치를 기준으로 상대경로를
   계산하기 때문입니다)
4. 폴더 안의 모든 `.html`을 재귀적으로 찾아서 왼쪽에 나열합니다. `node_modules`, `.git`,
   `dist`, `build` 등은 자동으로 건너뜁니다.
5. 페이지를 클릭하면 상단에서 체크한 폭들(기본: 390 / 768 / 1920)로 나란히 미리보기.
   체크박스로 폭 추가/제거 가능.
6. 다음에 다시 열면 **"다시 연결"** 버튼만 누르면 됩니다 (매번 폴더를 새로 고를
   필요 없음 — 브라우저가 권한을 기억하되, 보안상 세션마다 한 번은 재확인이 필요합니다).

## 페이지 이름/그룹 커스터마이징 (`pages.js`)

기본적으로는 파일명이 그대로 표시되고, 최상위 폴더명으로 그룹이 자동 지정됩니다.
더 보기 좋은 이름/순서를 원하면:

1. `pages.example.js` 를 같은 폴더에 `pages.js` 로 복사
2. 아래 형태로 채우기:

```js
window.PAGES_CONFIG = {
  groupOrder: ["주요 화면", "부가 화면"],  // 사이드바에 나열되는 그룹 순서
  pages: {
    // key: local-preview-board.html 기준 상대경로
    "home/index.html": { label: "홈", group: "주요 화면" },
    "product/detail.html": { label: "상품 상세", group: "주요 화면" },
  },
};
```

`pages.js` 에 없는 파일은 자동 발견되어 파일명 그대로, 자기 폴더명 그룹으로 표시됩니다 —
즉 `pages.js` 는 선택사항이고, 일부만 채워도 됩니다.

> **왜 `.json` 이 아니라 `.js` 인가요?** 브라우저가 `file://` 페이지에서는 보안상
> `fetch()`로 로컬 JSON을 읽는 걸 막습니다. `<script src="pages.js">` 로 불러오면
> 이 제약이 없어서, JSON과 거의 동일한 문법에 `window.PAGES_CONFIG = ` 만 앞에
> 붙인 형태를 씁니다.

## 왜 필요한가

- **디자인 교체 전 임시 대응처럼, 배포 전 정적 페이지를 실제 배포 없이 여러 폭에서
  한눈에 검수**하고 싶을 때
- 뷰포트를 하나씩 리사이즈해가며 확인하는 대신, 자주 쓰는 폭들을 한 화면에 고정해두고
  페이지만 갈아끼우며 보고 싶을 때
- 여러 정적 사이트/개인 프로젝트에 재사용하고 싶을 때 (그래서 하드코딩 없이 폴더
  기반으로 만들었습니다)

## 한계

- Chrome(및 Chromium 기반 브라우저)에서만 동작합니다 — File System Access API가
  Firefox/Safari엔 없습니다.
- 진짜 모바일 기기 에뮬레이션(터치 입력, User-Agent)은 안 됩니다. 뷰포트 **폭**만
  바뀝니다 — `@media (hover:hover)` 처럼 입력장치를 구분하는 CSS가 있다면 그 부분은
  실제 모바일과 다르게 보일 수 있습니다. (여러 폭을 한 화면에 동시에 띄우는 구조상,
  브라우저 개발자도구의 기기 툴바 같은 탭 전체 에뮬레이션은 애초에 함께 쓸 수 없습니다.)
- 폴더 선택 권한은 브라우저/세션에 따라 만료될 수 있어 가끔 "다시 연결"이 필요합니다.
